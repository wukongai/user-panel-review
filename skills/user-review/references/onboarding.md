# 整理我的长期目标用户

用户不需要理解数据结构或填写专业画像表。Agent 通过自然语言对话，把用户已知的业务事实整理成可长期复用的目标用户。

## 两个入口

1. **先体验**：直接使用内置示例用户和内置示例文章，不创建私人数据。
2. **改成我的用户**：了解用户的业务和受众，形成候选，确认后长期保存。

## 一次只问一个问题

先复述用户已经说过的内容，再只问一个会改变用户分层的问题。优先顺序是：

1. 你提供什么内容、产品或服务？
2. 你最希望帮助哪类人完成什么事情？
3. 这些人处在刚了解、正在尝试、准备决定，还是已经深度使用的阶段？
4. 实际使用的人、付钱的人和批准的人是否不同？
5. 什么会让他们相信你，什么会让他们立刻拒绝？

已经从上下文得到答案的问题不要重复询问。不要一次发出问卷，不从年龄、性别或敏感身份开始分层。

## 候选摘要

通常建议 3～5 类差异明确的长期目标用户。每类只用普通语言展示：

- 这类人是谁；
- 他现在想完成什么；
- 主要困难是什么；
- 什么会建立信任；
- 什么可能导致拒绝；
- 哪些判断仍不确定。

不要为了凑数量拆分相近用户。用户可以直接说“第二类不对”“这类人太专业了”“再加一类购买决策者”。收到纠正后先更新候选，再进入确认。

## 保存前确认

面向普通用户只说：

> 以上是我准备长期保存的目标用户。你可以直接说“确认保存”，也可以说“第二类不对”“这类人太专业了”或“再加一类购买决策者”。

不得默认显示内部名称、ID、版本、文件路径、计划哈希或 Apply 命令。用户确认后，Agent 在后台生成并应用同一不可变计划；任何输入漂移都要求重新确认。

## 后续维护

模拟反馈可以提示“这类用户可能分得太粗”或“拒绝原因需要补充”，但不能自动改写长期目标用户。用户要求修改时，继续一次只问一个关键问题，并用业务变化摘要再次确认。

私人数据必须位于 Skill 安装目录之外。升级或重装 Skill 不应删除它。
