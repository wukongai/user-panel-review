# Persona 治理

## 证据标签

准确分配一个来源标签：

- `grounded`：源自有记录的访谈、分析数据、支持记录或其他具名证据。
- `inferred`：从 grounded 证据推断而来，并列出假设。
- `operator_hypothesis`：根据操作者经验定义，但没有附带源证据支持。
- `synthetic`：作为测试视角生成，没有直接用户证据。

不要因为 Persona 产生了看似合理的输出就提升其来源等级。

## 稳定 Persona 要求

必须具备：

- 唯一的 `id` 和语义版本；
- 支持的内容细分领域；
- 来源、证据来源、置信度、假设和排除项；
- 待完成任务、上下文、痛点信号、信任信号和拒绝信号；
- 验证状态和评审日期。

迁移的旧 Persona 属于 `operator_hypothesis`，置信度为 `low`，且未经验证。其人口统计和购买假设是假说，不是事实。

## 动态 Persona 生命周期

1. 解释稳定目录为何遗漏了重要细分群体。
2. 使用 `assets/persona-template.md` 在运行目录内创建 Persona。
3. 设置 `provenance: synthetic`、`validation_status: unvalidated` 和 `generated_for_run`。
4. 默认只在本次运行中使用。
5. 只有获得明确批准并补充证据后才可提升。提升属于维护源代码变更，必须单独评审。

## 抽样

- 与其堆叠许多表面的人口统计变体，不如优先选择具有不同任务、上下文和失败模式的小面板。
- 不要把漏斗标签当作 Persona 会转化的证据。
- 不要把专业评审者计作用户投票。
- 面板超过宿主安全并发上限时，分批运行 worker，并在批次之间持久化状态。
