# 综合策略

## 类别

将最终综合组织为：

- consensus：来自多个 worker、实质相似且有证据支持的反应；
- divergence：worker 对同一段落作出不同解读；
- minority：独特但与决策相关的视角；
- strategic non-target rejection：声明的非核心受众预期会拒绝；
- preserve：修改后应保留的优势；
- professional risk：单独分配的领域评审者发现的问题；
- human validation：需要真实用户证据验证的假设。
- method findings：按方法 ID、版本和维度分区的观察；相同原文可保留多个方法来源。

## 规则

- 使用数量、worker ID 和序数信号；不要制造百分比。
- 绝不要因为大多数合成 Persona 不同意，就抹去少数发现。
- 不要把专业安全发现合并进受欢迎程度投票。
- worker 缺失或无效时，只要仍满足法定人数，就将运行标记为 `partial`。
- 除非每个计划中的 Persona 都有有效结果，否则不要写“所有 Persona”。
- 原始结果保留精确引语；综合内容使用带 trace ID 的简短释义。
- 不得把不同方法包的相似发现压成无来源结论，也不得从 DBS 维度生成总体传播分数。

## 学习提升

报告可以输出拟议的写作规则。提升必须满足：

1. 声明明确的细分领域和内容类型范围；
2. 人工批准；
3. 一个 development case；
4. holdout 或负迁移检查；
5. 明确的 apply 批准。

在此之前，将规则状态保持为 `proposed`。
