# user-review 2.0 自然语言双层交互设计

日期：2026-08-17  
状态：已确认设计，待实施

## 1. 背景与失败模式

`user-review` 2.0 已具备内置示例用户、长期用户画像、单次临时画像、分组选择、不可变运行快照、备份与恢复等能力，但当前公开手册和 Agent 入口直接向普通用户展示 `Persona`、`Panel`、`Audience Workspace`、计划哈希、文件路径和命令行。

这造成“内部工程结构泄漏到用户界面”：用户本来只想描述业务、维护目标用户并获得内容反馈，却被要求先学会专业名词和命令。仅重写手册不能解决问题，因为 Agent 仍会按根 Skill 和示例输出内部术语。

## 2. 设计目标

把产品改成双层交互：

1. 普通用户只需用自然语言说明业务、目标用户和待反馈内容，不预设其属于 AI、教育、心理、美妆或任何特定领域；
2. Agent 自动完成目标用户整理、长期维护、本次参与者选择、变更保护和运行快照；
3. 内部工程结构继续存在，但默认不向普通用户展示；
4. 中文对外统一使用“目标用户反馈”或“模拟用户反馈”，不把结果包装成专家评审、真实访谈或市场验证；
5. 开源新用户能按一条线性路径完成首次体验和个性化，不需要 Content Factory 或项目级 Skill 副本。

## 3. 双层结构

### 3.1 第一层：自然语言用户界面

普通用户默认只看到以下概念：

- 内置示例用户；
- 我的长期目标用户；
- 本次特殊用户；
- 参与本次反馈的用户；
- 模拟目标用户反馈；
- 将要保存的变化；
- 确认后保存或开始。

Agent 不主动展示以下内部名词：

- `Persona`、`Panel`、`Audience Workspace`；
- `Preview`、`Apply`、计划哈希、内部 ID；
- 文件路径、schema、manifest、worker；
- `education`、`consideration`、`decision` 等内部场景枚举。

只有用户明确要求开发、自动化、排障或审计细节时，才进入开发者说明。

### 3.2 第二层：专业执行内核

现有底层能力保持不变：

- 私人长期数据与 Skill 安装目录分离；
- 长期画像支持新增、修改、派生、停用和恢复；
- 每次运行选择合适的参与者，并允许单次特殊画像；
- 所有长期写入仍经过不可变计划、用户确认、漂移检查、备份和回滚；
- 历史反馈使用当次快照，不随以后画像修改而变化；
- 每个模拟用户独立产生反馈，汇总保留共识、分歧和少数意见。

这些机制由 Agent 自动调用。安全确认必须存在，但对普通用户表达为“这是我准备保存的变化，确认后再保存”，而不是要求用户理解哈希或命令。

## 4. 普通用户五步主流程

公开手册、根 Skill 路由、使用示例和真实行为回归必须使用同一顺序。

### 第一步：安装

只展示标准安装方法和一句重新打开会话的提示。源码克隆、迁移和命令行不进入新手主流程。

### 第二步：用内置用户体验

用户可以说：

> 我想先试试。请用内置示例用户看看这篇文章，告诉我这些用户会怎么理解、喜欢什么、担心什么。

Agent 用普通语言介绍本次会模拟哪些用户及选择原因，确认后运行。用户无需创建私人数据。

内置演示当前选择一篇 AI 文章和对应示例用户，只用于帮助用户快速看到效果，不代表 Skill 限定于 AI 内容。手册必须明确用户以后可以换成教育、心理、美妆、消费品牌、课程或其他领域的长期目标用户；当前正式回归对象仍是文章。

### 第三步：定制我的长期目标用户

用户可以说：

> 我想改成自己的目标用户。我主要提供____，希望帮助____。

Agent 复述已知信息，一次只问一个会改变用户分层的关键问题。渐进追问是 Agent 自己的职责，用户不需要在提示词中要求“一步一步问”或“一次只问一个”。形成候选后，用自然语言说明每类用户的任务、阶段、痛点、信任和拒绝信号，以及还不确定的部分。用户可以直接说“第二类不对”“再加一类购买决策者”。

确认前只展示将要保存的变化；确认后由 Agent 在后台安全保存为长期目标用户。

### 第四步：反馈我的内容

用户可以直接提供自己的文章并说：

> 请让我的目标用户看看这篇文章，告诉我他们的第一感受、看不懂的地方、信任或怀疑的原因，以及最希望我补充什么。

Agent 自动选择本次参与者，用自然语言说明选择理由，确认后生成模拟反馈。输出必须区分共同反馈、不同意见和需要真人验证的假设。

### 第五步：可选的本次特殊用户

只有用户主动提出特殊受众或 Agent 发现关键缺口时才进入此步：

> 这次还要特别考虑已经买过很多 AI 工具、但担心数据安全的人。

Agent 默认把该用户只用于本次，不自动写入长期画像。若用户明确要求以后持续使用，才进入长期变更确认。

## 5. 交互规则

1. 先帮助用户看到价值，再引导配置；不得把建立长期画像设为首次体验前置条件。
2. 一次只问一个会实质改变用户分层的问题。
3. 上一条是 Agent 交互契约，不得转嫁成要求用户写入提示词的操作说明。
4. 不要求用户提供专业画像字段；Agent 从自然语言中提取并以普通语言复述确认。
5. 默认给出建议，不把内部选项清单和配置表交给用户填写。
6. 用户可以随时用自然语言修改，例如“这类人太专业了”“把购买者单独考虑”“这次先不要保存”。
7. 长期变更必须确认，但普通用户只确认业务含义和变化摘要。
8. 不默认显示内部路径、哈希、ID、状态枚举或命令。
9. 始终披露这是 AI 模拟反馈，不是真实用户研究或效果预测。

## 6. 用户文档结构

主中文手册重写为：

1. 这个 Skill 能帮你做什么；
2. 安装；
3. 第一次体验：让内置示例用户看一篇文章；
4. 改成我的长期目标用户；
5. 让我的目标用户反馈自己的内容；
6. 可选：增加本次特殊用户；
7. 如何继续修改长期目标用户；
8. 能力边界和常见问题。

命令行、内部目录、数据结构、计划哈希、迁移和故障排查移到独立开发者指南。README 保持安装与五步快速体验，不复制完整手册。

中文手册同时作为独立内容排版并同步到布丁。GitHub 手册与布丁文章应共享同一正文事实源或通过受控同步生成，避免两份内容长期漂移。

## 7. 真实对话 Use Case 与截图

不再把工程审计记录当作用户体验截图。新增一次从远程安装副本开始的真实 Agent 多轮模拟，使用虚构示例业务，按五步流程执行：

1. 用户要求先体验内置示例用户；
2. Agent 用普通语言介绍参与者；
3. 用户提交示例文章并得到反馈；
4. 用户通过多轮自然语言定制长期目标用户，并纠正至少一处候选；
5. 用户提交自己的内容并得到反馈；
6. 用户增加一个仅本次使用的特殊用户并再次获得差异反馈。

对话输入可以预先编排，Agent 输出必须来自实际安装后的 Skill 运行。截图使用脱敏后的真实转录排版，不暴露本机路径、哈希、内部 ID、私人内容或凭证。手册中按操作顺序插入截图，并明确“示例为 AI 模拟，不是真人研究”。

## 8. 测试与验收

### 8.1 确定性回归

- 主手册五步顺序固定；
- 主手册和普通用户示例不得出现 `Persona`、`Panel`、`Audience Workspace`、计划哈希和 Apply 指令；
- 普通用户提示词不得包含“请一步一步问我”或“一次只问一个问题”；这些行为由根 Skill 和创建引导自动保证；
- 手册明确 AI 文章是内置演示，并用学生、老师、美妆等跨领域例子说明长期目标用户不受领域限制；
- 开发者指南保留完整内部命令与安全边界；
- 根 Skill 明确默认自然语言界面和按需技术详情；
- 报告用户可见标题改为“模拟目标用户反馈”；
- 内部 schema、CLI 和已有 2.0 数据兼容测试继续通过。

### 8.2 真实 Agent 行为回归

- 首次体验不要求创建或理解用户空间；
- 定制目标用户时一次只问一个普通语言问题；
- 候选摘要不主动展示内部英文名词、路径或哈希；
- 用户用自然语言纠正一类目标用户后，Agent 能更新建议；
- 本次特殊用户默认不进入长期保存；
- 用户要求专家评审、真实转化预测时继续拒绝越界。

### 8.3 完成标准

- 全量 pytest、Ruff、Skill validation、凭证检查和 diff check 通过；
- Skill Engineering Doctor 的结构结果与真实行为评测分别报告；
- 从远程安装候选完成五步真实回归；
- 真实对话截图完成并进入中文手册；
- 布丁同步成功并返回可核对记录；
- GitHub README、中文手册、版本说明和测试证据一致。

## 9. 兼容性与非目标

- 仓库名、Skill 安装名和触发名继续使用 `user-review`；“用户评审”保留为兼容触发词，不作为默认中文产品输出。
- 底层 `Workspace`、`Persona`、`Panel`、CLI 参数和 schema 暂不重命名，避免破坏已有数据和自动化。
- 本改版不创建 Expert Review、Content Review，不引入专业方法、理论量表或 DBS 方法层。
- 文章仍是已完成真实回归的主线；不因交互改版扩大对落地页、课程、视频、真实投放或效果预测的支持声明。
- 不把私人画像、真实文章或完整私人对话提交到公开仓库。

## 10. 公开截图的连续教育示例

公开手册保留第 1 张内置 AI 文章演示，用来证明安装后无需配置即可试跑。第 2～5 张必须改为同一条教育场景的真实连续会话，避免让用户误以为 `user-review` 只服务 AI 自媒体：

1. 内容提供者面向高中学生，同时服务家长和老师；
2. Agent 自动逐步澄清并形成候选目标用户，用户提示词不负责规定“一次只问一个问题”；
3. 用户修改至少一处学生分层，确认后保存为长期目标用户；
4. 同一批长期目标用户反馈一篇学习方法文章；
5. 临时增加“临近高考、焦虑且寻找立刻提分办法的学生”，只补充本次差异反馈，不进入长期保存。

第 2～5 张的参与者名称、业务背景和文章主题必须连续一致。截图只能来自远程默认分支全新隔离安装后的真实 Agent 输出；公开转录可以删除本机路径、内部哈希和过程日志，但不得改写 Agent 的最终回答。录制说明必须如实说明第 1 张与第 2～5 张来自两次隔离会话。
